## 已确认事实与待澄清项

- 用户确认桌面端可以登录，iOS 的 Host、User、Port 完全一致。
- 输入特征为多级域名、包含 `@` 和连字符的用户名、端口 22、密码登录。真实账户标识不复制进测试夹具。
- iOS 弹窗为 `The operation couldn’t be completed. (NIOSSH.NIOSSHError error 1.)`；截图不能确定失败阶段或具体错误类型。
- 本地模拟器保留 0.2.2 (4) 和 0.2.0 (2) 两个版本。以最新 0.2.2 (4) 为复现基线，后续已通过设备 Info.plist 确认手机原版本也是 0.2.2 (4)。
- 后续诊断确认失败在认证前的主机签名协商；RSA-SHA2 修复后设备现存密码认证成功。完整证据见 research.md / validation.md。不要求用户提供密码到聊天或文档。

## User Scenarios & Testing

### US1 — 使用已有网关账户登录（P1）

用户以与桌面相同的配置，在 iOS 建立 SSH 连接并打开交互终端。

1. 给定可达的目标服务、有效凭据和已确认的主机指纹，点击连接后建立会话，Terminal 能收发数据。
2. 给定用户名 `test-account@ZONE-M6`，编辑、保存、重新加载和认证全过程保持字符与大小写一致，不按 `@` 拆分。
3. 给定认证失败或服务不兼容，连接结束并显示可理解的错误，不假报成功。

### US2 — 失败可诊断（P1）

1. 给定 DNS、TCP、协商、主机验证、认证或通道失败，显示已知阶段及可操作说明；未知错误明确标记未知，保留脱敏技术类型供排查。
2. 单独的监控命令或 SFTP 不受支持，不应误报为密码错误或阻止已有终端使用。

### US3 — 既有连接不回退（P2）

普通域名、IPv4、IPv6 和现有私钥登录保留原行为；已有会话、凭据与主机指纹不丢失。

## Requirements / 业务规则

- FR-001：Host、User、Port 独立处理。不得拼接 SSH URL 再反向拆分；用户名作为不透明字符串，保留 `@`、连字符与大小写。
- FR-002：Host 允许正常域名和 IP；沿用去除 Host 首尾空白的行为。端口为 1…65535，空 Host、空用户名和非法端口不得连接。Host 内填完整 ssh 命令/URL不属于本次新增能力。
- FR-003：密码、私钥、私钥口令不得被规范化、日志化或写入测试报告。保存策略沿用 Keychain。
- FR-004：只有认证成功才显示 Connected；失败、取消、重试不得残留连接任务或旧会话回调。
- FR-005：显示有证据支持的失败阶段；不能仅凭 `error 1` 解释为地址错误或密码错误。
- FR-006：保持首次主机指纹确认和指纹改变拒绝连接，不通过关闭验证修复兼容性。
- FR-007：如复现证据表明需要 keyboard-interactive、多步认证或新增算法，先补充规范和影响说明，再确认扩展范围；不默认启用弱算法或自动提交密码到任意提示。
- FR-008：Monitor / Terminal / SFTP 的能力失败独立呈现，不要求目标服务器必须支持 Linux 监控和 SFTP 才能使用终端。

## Edge Cases / 边界

无效或不存在域名、IPv6、非默认端口、网络超时、错误凭据、缺失凭据、主机指纹改变、用户拒绝指纹、取消后重连、后台断开、服务端拒绝 exec/PTY/SFTP。

不包含跳板机配置、SSH 隧道、自动重连、桌面应用改造、服务器配置修改或完整 SSH URI 导入。若目标实际依赖这些能力，先记录范围冲突。

## Success Criteria / 验收矩阵

| ID | 可观察的通过标准 | 验证方式 |
|---|---|---|
| AC-01 | 同一有效配置在目标 iOS 设备前台连续手动连接 3 次成功，终端能输入并得到回显 | 真实目标验证；未执行不得标通过 |
| AC-02 | 含 `@` 用户名在 UI 保存、Codable 往返、认证请求中的值逐字一致 | 单元 + 受控 SSH 服务端认证请求断言 |
| AC-03 | 密码认证成功/拒绝均符合预期，不因域名或用户名形式误判 | 真实 SSH 协议集成测试 |
| AC-04 | DNS/TCP、协商、指纹、认证和未知错误有准确或明确未知的提示，诊断无秘密 | 故障注入 + 错误呈现测试 |
| AC-05 | 普通域名、IPv4、IPv6、非默认端口、Ed25519/RSA 既有支持不回退 | 参数测试及支持能力的集成测试，区分未验证项 |
| AC-06 | 指纹改变拒绝连接；拒绝、取消后可重试，无旧回调污染 | 会话集成测试 |
| AC-07 | 监控或 SFTP 被拒绝时，已建立的可用终端继续使用 | 限制通道能力的 SSH 夹具 |
| AC-08 | 原配置、Keychain 和指纹记录保持兼容，完整现有测试通过 | 回归与迁移测试 |

## Assumptions / 确认门槛

网络可达且账户在测试时有效。桌面成功是用户已确认的事实，尚未在本轮独立复现。规范及条件性方案确认后才开始实现；出现能力扩展、需求冲突或验收偏差，先记录问题、影响和修正方案。

## 2026-10-17 已确认变更

用户确认采用 RSA-SHA2，保持现有安全策略。主机 RSA 验签只新增 rsa-sha2-256/512，不新增 ssh-rsa/SHA-1 回退；最低 RSA 2048 位。RSA 公钥的 wire 格式仍为 ssh-rsa，指纹沿用同一个公钥，不能因编码名称混淆签名策略。

AC-07 复现出附加偏差：仅拒绝 SFTP subsystem、不主动关闭通道的服务器会使依赖等待初始化。已限定修正为失败初始化并关闭子通道，保留连接和终端；不扩展到其他监控协议。
